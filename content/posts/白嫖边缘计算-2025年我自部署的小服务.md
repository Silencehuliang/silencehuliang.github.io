## 前言

这两年我有一个很强烈的感受：**个人开发者部署一个服务的成本，正在无限趋近于零**。Cloudflare Workers、Vercel 这类平台把"服务器"这件事变成了免费额度内的边缘函数。2025 年我陆陆续续自部署了好几个小服务，这篇文章做个盘点，一方面记录踩坑，另一方面也给自己留个"资产清单"。

## 1. MoeMail:临时邮箱

临时邮箱是折腾各类"注册-验证"场景的神器。我部署的是开源项目 [MoeMail](https://github.com/beilunyang/moemail)，基于 NextJS + Cloudflare 技术栈：

- 前端 NextJS 部署在 Vercel
- 邮箱收件能力靠 Cloudflare Email Routing 把邮件路由到 Worker 处理
- 数据存 D1

部署完绑定自己的域名，就能随用随生成临时邮箱。需要注意的地方是**邮箱域名配置**和 DKIM 相关设置，照着文档一步步来问题不大。

## 2. Gemini API 代理

Gemini 的 API 在国内直连比较困难，官方给的免费额度其实不少，缺的只是一条通畅的路。我先后试了 [gemini-balance](https://github.com/Welcome-Whitehat/gemini-balance) 和它的边缘函数轻量版 gemini-balance-lite：

- 把 Gemini API 中转成 OpenAI 兼容的接口
- 支持聚合多个 API Key 做轮询/负载均衡，免费额度成倍叠加
- 部署在 Vercel/Cloudflare 边缘函数上，国内配个自定义域名就能用

这类代理的通用姿势是：**客户端 → 边缘函数(海外) → 上游 API**，中间加一层 Key 池和简单的转发逻辑。搞完之后 AIStudio 申请的免费 Key 终于能稳定用起来了。

## 3. filehelper:匿名文件传输助手

手机和电脑之间传个文件、临时给别人发个链接，微信文件传输助手很方便但离不开微信。于是写了一个极简的匿名文件传输助手 filehelper：打开网页、传文件、得到一个取件码/链接，对方打开就能下载，过期自动清理。

核心就几件事：对象存储放文件、边缘函数做签名上传和下载、TTL 过期策略。代码量不大，但"从需求到上线一个晚上搞定"这件事，放在五年前要用 Django + 一台 VPS 折腾好几天。

## 4. openai-gemini

配合上面 Gemini 代理做的另一个小玩具：把 OpenAI 的接口格式转成 Gemini 的调用，这样一堆只支持 OpenAI 格式的客户端就能直接吃到 Gemini。纯 JavaScript 实现，部署在边缘函数上，也是一次很好的"边缘函数练手"。

## 小结

盘点下来，2025 年我部署的服务全部跑在免费额度上，零服务器、零运维。这套"边缘函数 + 对象存储 + Serverless 数据库"的组合拳，就是这一年的主题。2026 年要在这个基础上做点真正的产品，后面再写。
